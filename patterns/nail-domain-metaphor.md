# 钉子域 / 假钉子隐喻

## 长什么样

文里突然抛出「钉子」「钉子域」「钉死」「钉子户式」一类说法，当成已经约定俗成的技术或产品概念，但前后没有定义，也没有对应真实对象。

常见变体：

- 「这个钉子域还没封住」
- 「先把几个钉子钉死」
- 「属于某某钉子」
- 把「钉 SHA / 钉版本」这种本来有具体动作的说法，扩成空壳隐喻到处用

## 外部证据

- 「**钉死**」已有中文口癖元讨论，见 [`ding-metaphor.md`](ding-metaphor.md) / scrape 少数派 + 说人话。
- 「**钉子域**」「**钉版本**」作为独立黑话词条：本轮中文检索未找到口癖元讨论（空）。Justin 种子观察仍保留。

## 为什么算 slop

- 听起来很「工程」，其实读者不知道指什么。
- 用隐喻代替命名：该说「固定版本号 / 固定提交 / 固定数据源」时，却说「钉子」。
- 容易传染：一篇里出现一次，后面就跟着造更多「域」。

## 更好的说法（示例）

| 空壳 | 改成 |
|------|------|
| 钉子域 | 直接写对象：官方仓库、数据集版本、接口约定 |
| 钉死这个域 | 固定到具体提交 / 标签 / 文件路径 |
| 还有几个钉子 | 还差哪几项可核对的证据 |
