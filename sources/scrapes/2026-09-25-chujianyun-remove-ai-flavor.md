# 去除 AI 味道

## 目标

把内容从“正确但像 AI 总结”改成“自然、具体、像人在认真讲一件事”。

优先保留作者的观点、判断、材料和语气，不把文章改成另一种人格。这个 skill 不是为了追求“检测器通过”，而是为了提升真实读者的阅读感。

## 使用边界

如果用户没有提供原文、文件路径或明确的待改片段，先索要文本，不要凭空示范。

这个 skill 只处理表达质感和读者阅读感，不负责事实核查、资料补充、选题策划、标题生成或平台格式排版。遇到事实可疑、数据缺来源、观点缺证据时，保留原意并提醒用户需要另行核查。

## 判断模式

先判断用户要哪种处理深度：

- `诊断模式`：用户说“看看哪里有 AI 味”“先审一下”“帮我标出来”。只输出问题清单和改写建议，不直接重写全文。
- `轻改模式`：文章基本可用，只是有少量套话、硬句、破折号、冗余连接。做最小改动。
- `深改模式`：文章像资料整理稿、翻译稿、AI 草稿或提纲稿，或每句话单看都顺、合起来却缺少主线和信息增量。需要重写开头、过渡、小标题、结尾和部分段落。
- `终稿模式`：用户明确要“可发布版本”“公众号终稿”“直接改好”。输出完整优化稿，并说明关键修改。

如果用户没有说明，默认使用 `轻改模式`；如果原稿明显不像成稿，升级到 `深改模式` 并说明原因。

## Gotchas

- 不要为了“像人写”而加入夸张情绪、口水话或油腻表达。
- 不要为了顺滑改掉作者立场、删掉关键限定条件，或发明原文没有的案例和结论。
- 不要把专业文章改成鸡汤、营销腔或段子文。
- 不要承诺可以绕过 AI 检测器；目标是让真实读者读起来更自然。
- 不要把所有列表都强行改成自然段；真正方便扫描的列表要保留。

## 工作流程

复制此清单并跟踪进度：

```text
去 AI 味进度：
- [ ] 步骤 1：判断处理深度
- [ ] 步骤 2：保留核心观点、事实和作者语气
- [ ] 步骤 3：识别 AI 味、资料味、翻译腔和模板句
- [ ] 步骤 4：按模式输出诊断、局部改写或完整终稿
- [ ] 步骤 5：自查自然度、具体性、节奏和可发布性
```

### 1. 先保留骨架

改写前先抓住这些内容：

- 文章最核心的一句话
- 必须保留的事实、数据、案例、术语
- 作者原本的立场和语气
- 读者为什么要读完
- 段落之间是否有推进，而不是只把正确句子堆在一起

不要为了顺滑删掉关键细节。不要擅自加入原文没有支持的新结论。遇到“单句好看、整体空心”的稿子，先重排主线、提纲和段落关系，再处理词句表面的 AI 味。

### 2. 再清理味道

优先处理这些高频问题：

- 套路开场：在这个时代、随着技术发展、众所周知
- 生硬连接：综上所述、基于此、由此可见、值得一提的是
- 空洞大词：卓越、革命性、颠覆性、重要意义、巨大价值
- 假金句：听起来很猛，但没有信息增量
- 内容空心：每句话都像写得不错，但合起来没有具体观点、证据或推进
- 破折号滥用：用 `——` 强行制造解释和转折
- bullet 堆叠：能写成自然段的内容，被硬拆成列表
- 加粗过多：每段都在强调，反而没有重点
- 翻译腔：语序像英文，抽象名词多，动作词少
- AI 高频词和三件套：反复使用“深入探索、复杂微妙、稳健、富有洞见”，或习惯性列三点、三连排比
- 判词腔：用“不是免费的 X 来源”“必须看起来 Y”这类负向定义、制度化判断表达观点，读起来像模型在下结论
- 资料味：元信息堆在开头，像笔记、讲义、PPT 备注

详细识别表和替换策略见 `references/anti-ai-flavor-rules.md`。当文章问题较多、需要系统处理时读取该文件。

### 3. 改写原则

- 删除套话，直接切入主题。
- 用具体场景、动作、数据替代抽象形容词。
- 先补主线和信息增量，再替换高频词；不要只做同义词清洗。
- 把负向定义改成正面判断或更像人会说的动作句，例如把“不是免费的可靠性来源”改成“可靠性没有那么简单”。
- 把长句拆短，让一句话只说一个主要意思。
- 用自然承接替代机械连接词。
- 少用排比，尤其避免三连排比和三点式总结成为默认节奏。
- 尽量不用 `不是……而是……`、`不仅……而且……更……` 这类模板句式；如果 A 和 B 都很抽象，通常要改成具体判断。
- 尽量不用破折号；改用冒号、逗号、句号、括号，或重排句子。
- 需要列表时保留列表；不需要时改回自然段。
- 对技术、产品、行业文章，保持准确克制，不改成鸡汤。

## 输出要求

### 诊断模式

输出：

```markdown
# 去 AI 味诊断

共发现 X 类主要问题：

## 1. [问题类型]
- 原文：...
- 问题：...
- 建议：...
- 示例改法：...

## 优先修改顺序
1. ...
2. ...
3. ...
```

### 轻改模式

输出“优化后文本”，再补充 3 到 5 条关键修改说明。不要写太长的诊断报告。

如果原稿来自文件，默认直接在回复中给出轻改结果，不新建文件；只有用户要求保存，或文本很长不适合直接回复时，才写入新 Markdown 文件，且不覆盖原文。

### 深改 / 终稿模式

输出完整优化稿。若原稿来自文件，写入新 Markdown 文件，不覆盖原文，默认命名为：

```text
原文件名-去AI味版.md
```

回复用户时说明：

- 已完成哪种处理模式
- 主要去掉了哪些 AI 味
- 新文件路径（如有）
- 是否已经接近可直接发布

## 自检清单

交付前检查：

- [ ] 是否保留了原文核心观点和关键事实
- [ ] 是否处理了“单句顺滑、整体空心”的结构问题

- [ ] 是否把生硬的负向定义、制度化判断改成更自然的判断或动作句
- [ ] 是否处理了破折号、过多 bullet、乱加粗
- [ ] 是否让开头更像人在开讲，而不是资料卡
- [ ] 是否让段落之间有自然承接
- [ ] 是否让结尾有收束，而不是像清单结束
- [ ] 是否避免把专业文章改成鸡汤或营销腔
```

# 去 AI 味规则表

## 识别特征

| 类型 | 典型表现 | 处理方向 |
|------|----------|----------|
| 套路开场 | 在这个快速发展的时代、随着 AI 的发展、众所周知 | 删除铺垫，直接进入问题或场景 |
| 生硬连接 | 综上所述、基于此、由此可见、鉴于上述 | 改成自然承接，或直接删除 |
| 空洞大词 | 卓越、革命性、颠覆性、重要意义、巨大价值 | 用事实、数据、场景、结果替代 |
| 假金句 | 句子很响，但没有新信息 | 删掉，或改成具体判断 |
| 内容空心 | 每句话单看都通顺，合起来却没有主线、证据、细节或推进 | 先补结构和信息增量，再改词句 |
| 破折号滥用 | A——B、观点——解释、概念——定义 | 改用冒号、逗号、句号、括号，或重排句式 |
| 模板对立句 | 不是 A，而是 B | 直接说 B，或写成递进关系 |
| 空泛对立句 | 不是关于速度，而是关于可用性；不是基础设施，而是架构 | 如果 A/B 都抽象，改成具体对象、动作和判断 |
| 复杂排比 | 不仅 A，而且 B，更 C | 拆成短句，保留真正重要的信息 |
| 三件套节奏 | 连续使用三点式列表、三连形容词、三个并列动词 | 保留必要枚举，打破默认三连节奏 |
| bullet 堆叠 | 每段都是列表，像 AI 总结 | 必要列表保留，其余改成自然段 |
| 乱加粗 | 每段都有加粗，重点过多 | 只保留真正影响理解的关键词 |
| 翻译腔 | 语序像英文，抽象名词多，动作词少 | 用自然中文重说，重心前置 |
| 名词贫血 | 稳健且结构清晰、富有洞见、全面深入，但读者不知道具体指什么 | 补具体名词、对象、材料和动作 |
| AI 高频词 | nuanced、delve、robust、insightful；复杂微妙、深入探索、稳健、富有洞见 | 不做机械禁用，先判断是否真的有信息量 |
| 判词腔 | 用“不是免费的 X 来源”“必须看起来 Y”这类负向定义、制度化判断表达观点 | 改成更直接的判断、动作句或带人味的说法 |
| 资料味 | 元信息、背景、定义堆在开头 | 元信息后置，正文先开讲 |
| 讲义味 | 每段像定义，标题过于整齐 | 加入阅读牵引和轻微节奏变化 |

## 高频替换

| AI 味表达 | 更自然的处理 |
|-----------|--------------|
| 综上所述 | 所以 / 总的来说 / 直接说结论 |
| 鉴于此 | 因为这样 / 这也意味着 |
| 不难发现 | 删除，直接陈述 |
| 值得一提的是 | 删除，直接说 |
| 众所周知 | 删除，或补具体证据 |
| 具有重要意义 | 具体说明“对谁有什么用” |
| 这无疑是 | 删除“无疑”，用事实支撑 |
| 在这个快速发展的时代 | 直接进入具体问题 |
| 随着技术不断发展 | 说明具体变化是什么 |
| 让我们一起 | 改成具体行动或直接收束 |
| 深入探索 / delve into | 直接说要分析什么，或删除 |
| 复杂微妙 / nuanced | 写清楚到底复杂在哪里、分歧在哪里 |
| 稳健 / robust | 换成具体能力、约束或测试结果 |
| 富有洞见 / insightful | 写出那条洞见本身 |

## 内容空心和结构问题

AI 味最难处理的地方，通常不是某个词，而是“看起来都对，但读完没留下东西”。这类稿子不能只做词语替换，要先处理主线。

典型特征：

- 每个句子单独看都顺，合起来却没有明确判断。
- 段落之间只是并列摆放，没有因果、递进、转折或取舍。
- 形容词多，具体名词少；读者不知道作者到底在说哪件事。
- 观点听起来很大，例如“这改变了一切”，但没有说明改变了谁、什么流程、什么结果。
- 文章像直接从最终成文开始生成，没有先经过提纲、材料选择和结构取舍。

处理方向：

1. 先问：这篇文章最想让读者记住哪一句？
2. 再看：每一节是否为这句话提供了故事、证据、反例、解释或推进。
3. 删除只负责“显得重要”的句子，尤其是没有对象、动作和结果的句子。
4. 必要时先把文章压成提纲，调整顺序后再扩写，而不是在原段落里逐句润色。

| 原表达 | 问题 | 更自然的改法 |
|--------|------|--------------|
| 但它确实改变了一切 | 很响，但不知道改变了什么 | 具体写出改变点：它把原来需要三个人确认的流程，压成了一个人当天能完成的草稿 |
| 这不仅关乎效率，更关乎可用性 | 两边都抽象，像自动生成的对立句 | 直接说具体判断：速度只是表层，更关键的是小团队能不能随时把想法变成可测试版本 |
| 这是一篇结构稳健且富有洞见的文章 | 形容词堆叠，没有名词和证据 | 这篇文章最有用的地方，是把小团队快的原因拆成了三个具体动作 |

## 负向定义和判词腔

有些句子问题不在套话，而在“像模型下判词”：先用否定结构框住概念，再给一个抽象名词。它可能逻辑正确，但不像真人会讲。

典型特征：

- `不是 + 抽象名词/来源/机制/保证`
- `必须/需要 + 看起来/表现为/呈现出 + 抽象关系`
- `不能简单理解为/不应被视为/并非单纯的`
- 名词很多，动作很少，句子像制度说明或风控报告

处理方向：

- 能正着说就正着说，不必保留原来的否定框架。
- 能用动作说清楚，就少用“来源、机制、保证、解释、呈现”这类抽象名词。
- 如果是 `不是 A，而是 B`，先检查 A 和 B 是否都太抽象；如果是，就不要保留这个句式，改写成具体判断。
- 如果原文有锋利判断，可以保留锋利，不要一律改温和。
- 如果原文是专业语境，保留必要限定，但把句子重心放到读者能立刻懂的判断上。

| 原表达 | 问题 | 更自然的改法 |
|--------|------|--------------|
| 它们不是免费的可靠性来源 | “不是免费的 X 来源”像翻译腔和判词腔，抽象、绕 | 可靠性没有那么简单 / 别把它们当成白来的可靠性 |
| 但它对外的解释必须看起来合作 | “解释必须看起来合作”很制度化，动作不清楚 | 但它对外还要装作是合作的结果 / 但对外还得说成是双方合作出来的 |
| 这并不是一个单纯的效率问题 | 模板否定句，信息重心太晚 | 问题不只在效率 / 真正麻烦的不是效率 |
| 它不应被视为长期稳定性的保证 | 被动、抽象，像免责声明 | 别指望它长期稳定 / 它撑不起长期稳定 |

## 破折号替代

优先避免 `——`。可按语义替换：

- 解释关系：`A——B` -> `A，也就是 B` / `A：B`
- 补充说明：`A——尤其是 B` -> `A，尤其是 B`
- 强转折：拆成两句
- 定义关系：`A——一种 B` -> `A 是一种 B`

## 资料稿改文章

当原稿像资料、笔记、提纲或翻译稿时，按这个顺序处理：

1. 元信息后置：原文链接、作者、发布时间、来源不要挡在开头。
2. 开头先开讲：用一个真实问题、具体场景或作者判断引出主题。
3. 小标题文章化：不要全是“定义、特点、方法、总结”。
4. 段间补桥：让读者知道为什么从 A 讲到 B。
5. 结尾收回主判断：不要只用清单或“以上就是”结束。

## 句子改写法

优先使用这几种手法：

- 删：删掉没有信息量的套话、形容词、连接词。
- 拆：长句拆成两三句。
- 换：抽象词换成具体动作、对象、场景。
- 顺：把句子重心提前，先说结论，再补解释。
- 接：补一句自然过渡，让段落之间有关系。

## 风格边界

不要这样改：

- 不要为了像人写，加入夸张情绪。
- 不要为了顺滑，把事实和条件删空。
- 不要把技术文章改成鸡汤。
- 不要把克制判断改成营销腔。
- 不要改变作者原本立场。

## 最终质感

好的去 AI 味，不是把文章改得更花，而是让它更像一个具体的人在讲清楚一件具体的事：

- 有观点，但不端着。
- 有节奏，但不堆技巧。
- 有温度，但不油。
- 有信息密度，但读起来不费劲。
