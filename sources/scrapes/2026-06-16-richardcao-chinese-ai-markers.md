```markdown
# 中文 AI 味标记

这份清单只管中文文本里最常见、最容易局部识别的高风险信号。
它不是机械禁词表。

判断重点只有三件事：

- 密度高不高
- 是不是在替读者解释
- 功能是不是和上下文重复

如果已经进入长文、长篇、提纲或多文件层级，再同时看：

- [longform_validation_rules.md](./longform_validation_rules.md)
- [novel_longform_rules.md](./novel_longform_rules.md)
- [plot_outline_rules.md](./plot_outline_rules.md)

## 快速路由

- `1500` 字以内短中文文本默认先读本文件。
- 第一轮改后仍残留 `不是...而是...`、`真正 / 往往`、工程复盘腔、小标题排比或结尾升华时，转读 [residual_hotlist.md](./residual_hotlist.md)。
- 解释框、总结、对比句、抽象复盘词查第 1-4 节。
- 作者补半句、自我总结、模板过渡查第 5-8 节。
- 虚词、否定骨架、断句标点、过度清楚查第 8.1-8.4 节。
- 引语同腔、公共论述长段、汇报腔、安全限定查第 8.5-10 节。
- 长文、小说、提纲问题只用本文件举证，不在这里完成专项判断。

## 1. 解释框

- 也就是说
- 换句话说
- 可以看到
- 不难发现
- 值得注意的是
- 需要指出的是
- 某种意义上
- 从某个角度看

优先看：

- 内容本身不复杂，却多走一层说明

## 2. 命题化总结

- 本质上
- 归根结底
- 说到底
- 关键在于
- 核心问题是
- 真正难的是
- 这也是为什么

优先看：

- 事实还没展开，就急着下定义

## 3. 工整对比句

- 不是……而是……
- 不是……，是……
- 不是……那么简单
- 问题不在……，而在……
- 难点不在……，而在……
- 最重要的不是……，而是……
- 真正决定……的，还是……
- 真正起作用的，不是……

判断：

- 做辨异、识险、认知推进时可留
- 替读者归纳意义时优先改

## 4. 抽象复盘词

- 收口
- 路径
- 语义
- 边界
- 维度
- 颗粒度
- 取舍
- 约束
- 对齐
- 一致性

优先看：

- 是否在用抽象名词代替具体动作

## 5. 高频判断词

- 明确
- 清晰
- 稳定
- 完整
- 可控
- 典型
- 本质
- 大概率

优先看：

- 判断是否先于事实

## 6. 作者替读者补半句

- 原来
- 真正
- 所谓
- 这便是
- 这才是

优先看：

- 动作、情绪、现场已经立住，作者还要站出来点题

## 7. 写作者自我总结感

- 最值得记的有几条
- 这段过程大概就是这么个样子
- 如果给这段过程补一句最贴切的话

优先看：

- 叙述者是否跳到高位整理经验

## 8. 模板化过渡

- 到了这里
- 进一步来看
- 在这个基础上
- 与此同时
- 另一方面
- 先……再……最后……

优先看：

- 段落推进是否被照顾得太明白

## 8.1 虚词填缝回潮

- 同时
- 进一步
```

## residual_hotlist.md（节选）

```markdown
# 二层残留热点清单

这份文件只放第一轮去味后最容易残留的高频模式。它不是禁词表；先判断词句是否承担模板功能，再决定删、压、换或保留。

## 快速路由

- 短中文、公众号、评论、方法文默认查本文件。
- 小说、提纲、强体裁只在句式残留明显时查本文件；不要让本文件压过题材专项规则。
- 命中同一热点簇 `2` 处以上，或热点簇承担段落主骨架，必须回到正文二改。
- 事实类文本只能重排和压缩原文材料，不因本文件新增事实。

## 1. `不是 A，而是 B` 型定义漂亮病

触发形态：`不是...而是...`、`不只是...更是...`、`问题不在...而在...`、`与其...不如...`。

模板功能：把复杂判断整理成漂亮二分，替读者完成辨异和升格；段落看起来更聪明，但事实推进常停住。

优先改法：

- 前后事实已经够时，直接删掉定义框。
- 把二分判断落回具体动作、后果、对象压力。
- 必要辨异只留半句，不让它成为段落主骨架。

保留例外：

- 原文确实在做术语辨析、法律界定、技术边界或政策口径。
- 人物对白里这句话本身体现角色性格或关系位置。

## 2. `真正 / 本质 / 核心 / 关键` 型替读者下判断

触发形态：`真正`、`本质`、`核心`、`关键在于`、`说到底`、`归根结底`。

模板功能：把局部观察抬成结论，让作者像在整理答案；常和段尾盖章、正反定义连用。

优先改法：

- 删除锚点词，保留其后必要事实。
- 把高位结论改成“谁做了什么 / 产生什么后果 / 卡在哪里”。
- 结尾处优先停在未完全讲圆的摩擦或代价上。

保留例外：

- 学术、技术、政策文本中确有关键变量或核心概念。
- 原文 voice_sample 本来有明确的高位判断习惯。

## 3. `往往 / 通常 / 某种程度上` 型无证泛化

触发形态：`往往`、`通常`、`某种程度上`、`从某个角度看`、`某种意义上`。

模板功能：给没有证据的判断加稳妥外壳，把个人经验或局部事实说成普遍经验。

优先改法：

- 能落回原文例子就落回例子。
- 不能举证时删掉泛化，只保留局部判断。
- 改成时间、地点、对象或行动限制。

保留例外：

- 原文确有统计、调研、制度范围或专业经验支撑。
- 评论文需要克制表达，且没有成簇出现。

## 4. `路径 / 收口 / 落地 / 闭环` 型工程复盘腔外溢

触发形态：`路径`、`收口`、`落地`、`闭环`、`对齐`、`颗粒度`、`边界`。

模板功能：把生活、人物、叙事、评论都写成项目复盘，用抽象机制代替主体、动作和后果。

优先改法：

- 改回具体动作：谁在做、谁在承受、卡在哪里。
- 非工程题材中连续出现时，优先整段降抽象。
- 保留必要专业词，但拆掉它周围的解释胶水。

保留例外：

- 技术文、产品文、工程复盘本来需要这些词。
- 原文主题就是流程、接口、系统设计或代码协作。

## 5. 正反两面都讲一遍的安全补丁

触发形态：`当然，这不是说...`、`这并不意味着...`、`不能简单理解为...`、`也不是没有...只是...`。

模板功能：为每个判断补免责条款；文本显得稳妥，但推进变慢。

优先改法：

- 删掉不影响原意的让步句。
- 把必要限制并进事实条件，不单独成段。
- 只保留真正会影响读者误解的边界。

保留例外：

- 法律、医疗、政策、学术、技术说明需要风险边界。
- 原文本来承担合规、告知或操作口径功能。

## 6. `小标题 + 冒号 + 排比建议` 型方法文模板

触发形态：`第一，...`、`更重要的是，...`、`建议：...`、`关键动作：...`、连续短标题后接命令句。
```
